# Decisions

This file is the project’s lightweight decision log. Append entries; don’t rewrite history.

- 2026-02-17: Adopt **fail fast + loud** error handling. Avoid silent ignores in production code; either return/wrap errors or explicitly discard with a comment.
- 2026-02-17: Use basename-based wiki-link resolution and backlinks; enforce basename uniqueness within a vault.
- 2026-02-17: Basename uniqueness and wiki-link/backlink resolution are **case-insensitive** (canonical key = strings.ToLower(filepath.Base(path))).
- 2026-02-17: UX: Errors and user-facing messages should be **front-and-center** (overlay/prompt), not only the status bar. Validation errors during prompts keep the prompt open and render the message inside the prompt.
- 2026-02-17: Add deterministic Markdown auto-format on save (configurable via `auto_format_on_save`).
- 2026-02-17: Normalize vault path to an absolute path at startup to avoid Neovim CWD/path double-prefix issues.
- 2026-02-17: On Neovim buffer write, immediately re-index the saved note and refresh the info panel backlinks for the currently open note.
- 2026-02-17: Resizing: force a full Bubble Tea terminal repaint (`tea.ClearScreen`) on `WindowSizeMsg` to avoid persistent blank UI after terminal resizes; also signal Neovim with SIGWINCH after PTY resize.
- 2026-02-18: Finder UX: when no results match the query, show an explicit hint that Enter will create a note and require a confirm prompt before creating; cancel returns to the finder with the query preserved.
- 2026-02-20: Theme consistency: replace the hardcoded theme map with a single `internal/theme` package. Colors are extracted from Neovim highlight groups via RPC after applying the user's configured colorscheme, so the TUI automatically matches the editor. Config replaces `theme` with `colorscheme` (vim name) + `colorscheme_repo` (GitHub owner/repo for auto-install).
- 2026-06-10: Config editing in-app: `<leader>ce` opens `config.toml` and `<leader>cn` opens the managed nvim `init.lua` in the embedded Neovim; saving either hot-reloads the config (via the existing BufWritePost notification). Hot-applied settings: `colorscheme`, `colorscheme_repo`, `leader_timeout`, `auto_format_on_save`. Restart-required settings (`vault_path`, `nvim_mode`, `render_math`, `treesitter_parsers`) are reported in the status bar when changed. TOML parse errors keep the previous in-memory config and surface in the status bar instead of being silently ignored.
- 2026-06-10: Markdown diagnostics (issue #13): a pure-Go lint pass (`internal/markdown.Lint`) runs on note open and after save — never as-you-type — and is sequenced after format-on-save so it sees the formatted buffer. Results surface two ways: inline hints via Neovim's native `vim.diagnostic` API in a `kopr-diagnostics` namespace (signs/virtual text/underline for free, identical over SSH), and a quickfix-style panel below the editor (`<leader>md` toggles, Enter jumps to line:col; `<leader>mh` toggles inline hints). Initial rules: unterminated/malformed frontmatter, unclosed/empty wiki links, unresolvable wiki-link targets (same basename lookup as `gf`, so the warning never disagrees with jump behavior), duplicate headings, heading level jumps. Config: `diagnostics_enabled` and `diagnostics_inline`, both default true and hot-reloadable.
- 2026-06-10: Wiki-link `gf` semantics (issue #12): the `.md` suffix is optional in `[[links]]` and matched case-insensitively; `gf` resolves the link with the cursor anywhere inside `[[...]]` (brackets included); targets may contain spaces. Link detection/resolution is Go-side (Kopr remaps `gf` to an RPC notification), so behavior is identical in local and SSH mode. `FollowLink` failures (RPC, DB lookup, note creation) surface in the status bar instead of failing silently.
